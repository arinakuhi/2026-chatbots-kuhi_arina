# Лабораторная работа №2

## 1. Цель работы

Расширить функциональность Telegram-бота, разработанного в первой лабораторной работе, и реализовать работу с базой данных SQLite.

Основная цель — обеспечить постоянное хранение пользовательских данных в структурированной базе данных и реализовать операции добавления, получения, изменения и удаления данных.

## 2. Описание задачи

В рамках лабораторной работы был доработан Telegram-бот **Task Assistant Bot**.

Username бота: `@itmoftmi_AK_bot`

В первой лабораторной работе задачи сохранялись в JSON-файле.

Во второй лабораторной работе механизм хранения данных был изменён: для хранения задач используется база данных SQLite.

Бот позволяет:

- добавлять новые задачи;
- назначать задачам приоритет;
- просматривать список задач;
- отмечать задачи выполненными;
- удалять задачи;
- получать статистику по задачам.

## 3. Выбор источника данных

Для выполнения лабораторной работы была выбрана база данных SQLite.

SQLite была выбрана по следующим причинам:

- не требует установки отдельного сервера базы данных;
- входит в стандартную библиотеку Python через модуль `sqlite3`;
- позволяет хранить данные в структурированном виде;
- поддерживает SQL-запросы;
- подходит для небольших локальных приложений;
- позволяет реализовать полноценные операции CRUD.

Использование SQLite позволило заменить хранение данных в JSON-файле на работу с настоящей реляционной базой данных.

## 4. Структура базы данных

Для хранения задач используется файл:

`tasks.db`

В базе данных создаётся таблица:

`tasks`

Структура таблицы:

- `id` — уникальный идентификатор задачи;
- `user_id` — Telegram ID пользователя;
- `text` — текст задачи;
- `priority` — приоритет задачи;
- `done` — статус выполнения;
- `created_at` — дата и время создания записи.

SQL-запрос создания таблицы:

CREATE TABLE IF NOT EXISTS tasks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    text TEXT NOT NULL,
    priority TEXT NOT NULL,
    done INTEGER NOT NULL DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
)

Для каждого пользователя задачи хранятся отдельно по его Telegram user ID.

## 5. Основной функционал

В боте реализованы следующие команды:

- `/start` — запуск бота;
- `/help` — справка по командам;
- `/add <приоритет> <задача>` — добавление задачи в SQLite;
- `/tasks` — получение списка задач из базы данных;
- `/done <номер>` — отметка задачи как выполненной;
- `/delete <номер>` — удаление задачи;
- `/stats` — отображение статистики задач.

Поддерживаются три уровня приоритета:

- `high` — высокий;
- `medium` — средний;
- `low` — низкий.

Пример добавления задачи:

`/add high Подготовить Lab2`

## 6. Работа с SQLite

Для работы с базой данных используется стандартный модуль Python:

`sqlite3`

При запуске программы вызывается функция `init_db()`.

Она проверяет наличие таблицы `tasks` и создаёт её, если таблица ещё не существует.

### Добавление данных

При использовании команды `/add` выполняется SQL-запрос:

INSERT INTO tasks (user_id, text, priority) VALUES (?, ?, ?)

Использование параметров `?` позволяет передавать значения отдельно от SQL-запроса и уменьшает риск SQL-инъекций.

### Получение данных

Для получения задач пользователя используется запрос:

SELECT id, text, priority, done
FROM tasks
WHERE user_id = ?
ORDER BY id

Таким образом каждый пользователь видит только свои задачи.

### Изменение данных

Команда `/done` изменяет статус задачи:

UPDATE tasks
SET done = 1
WHERE id = ? AND user_id = ?

### Удаление данных

Команда `/delete` удаляет выбранную задачу:

DELETE FROM tasks
WHERE id = ? AND user_id = ?

## 11. Обработка ошибок

В программе реализована обработка следующих ситуаций:

- пользователь не указал текст задачи;
- пользователь не указал приоритет;
- указан неизвестный приоритет;
- вместо номера задачи введён текст;
- указан номер несуществующей задачи;
- в базе данных отсутствуют задачи пользователя;

Это позволяет избежать формирования SQL-запросов путём прямой конкатенации пользовательского ввода.

## 15. Преимущества SQLite по сравнению с JSON

По сравнению с JSON использование SQLite имеет несколько преимуществ:

- данные имеют определённую структуру;
- поиск выполняется с помощью SQL;
- изменение отдельных записей происходит без полной перезаписи файла;
- поддерживаются фильтрация и агрегация;
- проще масштабировать функциональность;
- легче добавлять новые поля и запросы.

Для данного проекта SQLite является более подходящим вариантом при увеличении количества задач и функциональности бота.
